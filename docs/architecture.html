实验四 · Pinia 状态管理整体架构

数据流：视图/组件 → 调用 Store 的 action/getter → 修改 state → 写入 localStorage；刷新时从 localStorage 恢复。

① 视图 / 组件层（views + components）
Home 个人主页 Login 登录 Admin / AdminEditInfo ProjectList / ProjectDetail ArticleList / ArticleDetail ProjectManage 项目管理 ArticleManage 文章管理 PageHeader 导航
▼ storeToRefs / 直接调用 action
② Store 层（src/stores，defineStore 定义）
User Store（useUserStore）
state：userInfo、token
getters：isLogin、userName、stuNo
actions：login、logout、updateInfo
持久化键：user_info、user_token
Project Store（useProjectStore）
state：projects、nextId
getters：projectCount、getProjectById、categoryList
actions：add / update / delete / persist
持久化键：project_list、project_next_id
Article Store（useArticleStore）
state：articles、nextId
getters：articleCount、getArticleById、categoryList
actions：add / update / delete / persist
持久化键：article_list、article_next_id
▼ actions 修改 state 后 JSON.stringify 写入；state 初始化 JSON.parse 读取
③ 持久化层（浏览器 localStorage）
user_info / user_token project_list / project_next_id article_list / article_next_id
④ 路由守卫（router/index.js 全局前置守卫 beforeEach）
访问 /admin 系页面（meta.requiresAuth） → 守卫内调用 useUserStore() → isLogin？ → 是 → 放行 / 否 → 跳转 /login?redirect=目标地址

示意结构：展示本项目 Store 划分、数据流与登录访问控制逻辑，非官方架构。
